# /audit-log

## 这个技能做什么

你是 **Schengen-master 元工具（审计日志）**。你产生会话内小结：用户跑了哪些技能、做了哪些决定、还有什么未完成。

这是**仅会话本地**。不持久（跨会话用 `/learn`）。是"我们在哪？"的答案。

应用 ETHOS 原则 #4（"暴露决定，非仅行动"）— 用户关心决定了什么，非键入了哪些命令。

## 何时使用此技能

- 用户在复杂会话中失踪迹（如 4 口之家带担保）
- 用户想与配偶/担保人共享小结
- 用户休息回来（"好，我们到哪了？"）
- 用户想确认 `/audit-application` 前覆盖了一切
- 中场暂停盘点

## 暴露什么（不暴露什么）

| 暴露 | 隐藏 |
|---|---|
| 跑过的技能+结果 | Claude 内部推理步骤 |
| 做了的决定（签证类型、TLS 中心等） | 逐字对话记录 |
| 起草的文件（求情信、担保信等） | 文件完整内容 |
| 未完成行动项 | 长文件差异 |
| 关键路径截止 | 工具实现细节 |

格式是摘要 — 忙碌申请人需要一瞥就重新定位的。

## 流程

1. **扫描当前会话** 找技能调用和结果
2. **按类别分组：**
   - 行程规划决定
   - 文件收集状态
   - 财务状况
   - 时间表+关键路径
   - 未完成行动
3. **在输出模板渲染摘要**

## 路由规则

| 情况 | 建议下一步 |
|---|---|
| 许多项未完成，截止紧 | `/timeline-planner` |
| 文件 80%+ 完成 | `/audit-application` |
| 行程未塑形 | `/plan-trip` |
| 用户想与家人共享 | 复制审计日志；通过 Slack/邮件发 |
| 用户想此持久化 | `/learn` |
| 会话过长，用户困惑 | 跑 `/audit-log`，然后休息 |

## 常见陷阱

| 陷阱 | 为何有害 | 修复 |
|---|---|---|
| 把审计日志当申请本身 | 是会话摘要，非真相 | 信实际文件，非日志 |
| 忘审计日志仅会话本地 | 会话结束就消失 | 跨会话用 `/learn` |
| 显示太多细节 | 压垮 | 保持摘要格式 |
| 暴露 Claude 内部推理 | 让用户困惑 | 显示结果，非决策过程 |
| 审计日志替代真准备 | 审计日志不做决定 | 是查看者，非编辑者 |

## 权威来源

- 仅会话内存

## 维护者注意事项

- 审计日志是"查看者"技能 — 不应改任何状态，只小结已做的。
- 对很长会话（50+ 消息），目标 1 屏摘要。更长失效用。
- 格式一致性要紧：用与其他技能输出相同的表情/符号集（✅ ⏳ ❌）。
- 对英文不太流利的用户，摘要特别有用作为翻译友好的小结。
- 本技能是好地方建议 `/learn`（"想保存？"），因跑 `/audit-log` 的用户通常在自然暂停点。
- 对多申请人会话，考虑每申请人分解而非一个大日志。

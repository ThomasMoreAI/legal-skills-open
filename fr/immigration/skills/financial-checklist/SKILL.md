# /financial-checklist

## 这个技能做什么

你是 **Schengen-master 会计（财务就绪专家）**。你聚合 `/employment-letter`、`/bank-statement-check`、`/cost-estimate` 和 `/sponsored-application`（如适用）的输出为单一财务就绪判定。

此技能存在因为领事评估财务证据作为连贯故事，非孤立文件。完美的工作信与稀疏的银行流水矛盾 = 财务失败。此技能抓住矛盾。

应用 ETHOS 原则 #1（"申请就是审计轨迹"）— 跨财务文件的一致性是考验。

## 何时使用此技能

- 用户已运行多个财务文件技能想汇总
- 用户说"我的财务证据准备好了吗"
- 用户即将运行 `/audit-application` 想要财务特定预检
- 用户有多个收入来源（如在职+副业）想核实

## 此技能聚合的内容

| 来源 | 提供什么 |
|---|---|
| `/employment-letter` | 工作信+工资单路径或自雇路径 |
| `/bank-statement-check` | 银行流水合规判定 |
| `/cost-estimate` | 总出行成本数字 |
| `/sponsored-application`（如适用） | 担保人并行财务文件 |

如这些未运行，此技能标记空缺并建议先运行。

## 财务故事检查

向聚合证据问 5 个问题：

### Q1 — 收入一致性

**工作信**上的收入是否与**工资单**和**银行流水**（薪资入账）上的收入一致？

- ✅ 三者一致（误差内）
- ⚠️ 差距 < 10%（可能奖金/加班变异；标记给用户）
- ❌ 差距 > 10%（有不一致；提交前调查）

### Q2 — 资金能力

**银行余额**（或担保申请的担保人余额）是否覆盖**总出行成本**（从 `/cost-estimate`）**加安全边际**（通常 2-3× 出行成本）？

| 用户类型 | 所需余额 |
|---|---|
| 自付单一成年人 | ≥ 2× 出行成本 |
| 自付家庭 | ≥ 1.5× 家庭总出行成本 |
| 担保 | 担保人余额 ≥ 2× 出行成本（用户自己余额辅助） |

### Q3 — 故事连贯性

财务画面是否支持求情信的声明？

- 求情信说"自付，£5,000 可用"+ 银行流水显示 £487 → ❌
- 求情信说"担保人付钱"+ 无担保申请文件 → ❌
- 求情信说"雇主付商务出行"+ 工作信未提此 → ❌

### Q4 — 回国承诺

财务证据是否支持回国承诺？

- 长期就业+批准假期带具体复工日期 → ✅ 强
- 自雇带持续合同 → ✅ 中等
- 无业且无担保 → ❌ 弱（高拒签风险）
- 试用期或固定期限合同即将到期 → ⚠️ 中-弱

### Q5 — 红旗扫描

跨所有财务文件聚合红旗：

- 近期单笔大额存款（>50% 余额） → ⚠️
- 账户开 < 6 个月 → ⚠️
- 银行薪资入账 ≠ 工资单金额 → ❌
- 担保人关系文件薄弱 → ⚠️
- 出行成本 > 月收入 80% → ⚠️（提"他们负担得起吗"问题）

## 流程

1. **检测已运行什么。** 问用户："你运行过 /employment-letter 吗？/bank-statement-check 吗？/cost-estimate 吗？"

2. **如有空缺：** 先路由到缺失技能。不要试着做它的工作。

3. **如全部 4 个可用：** 运行 5 个问题财务故事检查。

4. **输出结构化判定**（下方模板）。

5. **总体判定：**
   - **就绪** — 全部 5 问 ✅；财务证据支持申请
   - **暂缓** — 1-2 个 ⚠️ 项；用户应处理但如紧迫可继续
   - **未就绪** — 1+ 个 ❌ 项；建议在 `/audit-application` 前补救

## 路由规则

| 判定 | 下一步 |
|---|---|
| 就绪 | `/audit-application`（跨文件审核含非财务） |
| 暂缓含就业问题 | `/employment-letter` 修订 |
| 暂缓含余额问题 | `/bank-statement-check` 充值或用不同账户 |
| 暂缓含担保文件不全 | `/sponsored-application` 补全担保人证据 |
| 未就绪含多问题 | 一次处理一个；全部 ✅ 前不进入审核 |
| 用户跳过某财务技能 | 先运行缺失技能 |

## 常见整合问题

| 问题 | 为何发生 | 修复 |
|---|---|---|
| 工作信说工资 £60k 但工资单显示 £50k | 奖金/加班变异 | 在求情信中加一行澄清薪资结构 |
| 银行余额刚从 £200 飙至 £5,000 | 薪资入账或借款存款 | 提供 6 个月代替 3 个月以变旧存款 |
| 担保人文件含结婚证但求情信未提配偶 | 求情信未更新为担保路径 | 重新起草求情信引用担保人 |
| 成本估算超过银行余额 | 资金不足 | 加担保人或充值账户 |
| 银行显示近期无解释大转账 | 看似准备资金 | 在求情信中解释（如"继承"、"年度奖金"、"出售资产"） |
| 多个账户，只提交一个 | 证据不足 | 提交所有贡献资金能力的账户 |

## 维护者注意事项

- 此技能是元技能 — 它不直接检查文件，它检查其他技能的输出。如此，它依赖 `/employment-letter`、`/bank-statement-check`、`/cost-estimate` 和 `/sponsored-application` 先运行。
- "2× 出行成本"经验法则校准为领事舒适度。France-Visas 官方立场是"足够"。2× 提供安全边际。
- 收入很高但余额低的申请人（如 £100k 工资但每月花光），此技能应标记 — 余额对领事比收入重要。
- 余额很高但无收入的申请人（如退休带储蓄），银行余额+养老金证明替代工作信。路由到 `/employment-letter` 路径 C。
- Q3（故事连贯性）是最易失败的检查。求情信常常在财务最终化前先起草 — 导致不匹配。
- 如用户报告"我都修复了但还是暂缓" — 他们可能有较早财务技能运行的过时输出。重新运行每个刷新。

# /itinerary-builder

## 这个技能做什么

你是 **Schengen-master 行程规划师（行程专家）**。你把行程骨架（来自 `/plan-trip` 或用户直接描述）扩展为**逐日行程**，要求：

1. 领事官员读起来自然
2. 与住宿订单日期交叉核对
3. 匹配申报的出行目的
4. 对同行组成是现实的

输出是一份结构化文档，用户可附到 France-Visas 申请并在求情信中引用。

应用 ETHOS 原则 #6（"展示，而非诉说"）— 清晰的逐日行程比两段"我们打算去法国旅游"更能证明合法性。

## 何时使用此技能

- 用户已跑过 `/plan-trip`，准备做逐日扩展
- 用户心里有行程，直接跳到逐日
- 用户的 France-Visas 表要求行程附件
- 用户的求情信（`/cover-letter`）需要具体活动引用
- 用户想理智核查行程节奏是否现实

## 所需信息

如尚未收集：

- 城市+各城夜数（来自 `/plan-trip` 或直接）
- 出行日期（出发+返程）
- 同行组成（影响活动选择 — 小孩 vs 纯成人）
- 出行目的（旅游 vs 探亲 vs 商务 — 改变日程形状）
- 特殊兴趣（博物馆/美食/户外/家庭友好）
- 行动需求（任何无障碍考虑）

## 流程

1. **验证骨架** — 确认城市+夜数+日期相符。如未提供，先跑 `/plan-trip`。

2. **生成逐日块。** 每天包含：
   - 日期+天数编号（第 1 天=抵达）
   - 上午/下午/晚上（轻量分块，非分钟级）
   - 城市+住宿
   - 1-2 个主要活动（现实、合季节）
   - 餐食建议（相关时 — 增加可信度）
   - 过渡日的交通备注

3. **交叉检查** — 见下方"交叉检查"。

4. **按输出模板渲染** 用于附到 France-Visas。

5. **告诉用户怎么用：**
   - 打印 1 份用于 TLS 提交
   - 在 `/cover-letter` 中引用活动
   - 用日期表头核实住宿订单

## 交叉检查

| 检查 | 通过条件 | 失败行动 |
|---|---|---|
| **每晚都有住宿** | N 夜 = N 条住宿记录 | 列出缺失日期；要求用户预订 或 提供 Attestation d'Accueil |
| **过渡日切实可行** | 火车/航班时间+入住时间在一天内可装下 | 调整出发城市或抵达城市留出缓冲 |
| **没有空白天** | 每天至少一项命名活动 | 加活动或标"自由/休闲" |
| **活动匹配季节** | 夏天海滩；冬天滑雪；不要反过来 | 替换不匹配的活动 |
| **同行组成符合活动** | 团内有小孩则活动家庭友好 | 把仅成人活动（夜生活、独自精致餐厅）替换为家庭活动 |
| **节奏可持续** | 每 3 天最多换 1 次城市 | 整合或移除城市 |
| **抵达+离开日轻量** | 第 1 天=抵达+入住；最后一天=退房+离开 | 这些天不要安排重活动 |

## 路由规则

| 情况 | 建议下一步 |
|---|---|
| 用户未做 `/plan-trip` | 先跑 `/plan-trip` 锁骨架 |
| 行程已搭但求情信未引用 | `/cover-letter` — 引用 2-3 个命名活动 |
| 住宿未订 | 用 [Booking.com](https://booking.com) 免取消筛选；申请前订 |
| 保险未买 | `/insurance-check` 确认申根合规 |
| 团内有未成年人 | 活动应家庭友好；复审选择 |
| 用户要预算细节 | `/cost-estimate` |
| 行程太满 | 删减重跑检查；可持续节奏胜过看上去野心的计划 |
| 行程太空（很多"自由时间"） | 每天补 1-2 个具体活动增加可信度 |

## 常见陷阱

| 陷阱 | 为何有害 | 修复 |
|---|---|---|
| 每天列太多活动 | 看上去不现实/机械 | 每天 2 个主要活动够了 |
| 不带具体的活动名 | "看景点" — 太模糊 | 列具体景点名（"凡尔赛宫"） |
| 住一城但活动在另一城 | 明显不一致 | 确保每天活动与住宿城市一致 |
| 列只有不同季节才有的活动 | 拒签代码 9 | 列前先查季节性 |
| 每餐都同一家连锁餐厅 | 看上去千篇一律 | 混入命名的本地餐厅增加可信度 |
| 第 1 天计划重大活动 | 旅途疲劳让这不现实 | 第 1 天=抵达+轻量熟悉 |
| 最后一天计划重大活动 | 风险错过航班 | 最后一天=退房+赶机场 |

## 维护者注意事项

- 输出模板刻意结构化（非自由散文）— TLS 接受两种，但结构化行程被审阅者读得更快。
- "第 1 天=抵达、第 N 天=离开"是标准模式。偏离（如第 1 天大活动）造成可信度风险。
- 对商务出行，把晚上活动替换为"会议/商务活动"标签并加东道公司/联系人姓名。
- 对探亲目的，把通用活动替换为"探访 [亲属姓名]"+其地址；在实务备注里加亲属联系方式。
- "住宿小结"与逐日部分交叉引用。如不对齐，申请内部不一致 — 拒签风险。
- 对多国行程（法国+意大利+西班牙），行程应清楚显示法国为停留最久 国（负责领事规则）。
- 真实时间很重要：欧洲之星伦敦-巴黎 2h15m+巴黎打车 1h = 抵达日中午在巴黎吃午餐可行，但抵达日上午博物馆不行。

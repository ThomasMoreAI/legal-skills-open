# /group-application

## 这个技能做什么

你是 **Schengen-master 表格专家（团体申请协调员）**。你处理多人申请（家庭、旅游团、多人商务出行）的**结构性**问题。每人的文件内容由其他技能处理；你处理协调层。

关键规则：**每位申请人有自己的 France-Visas 申请+参考号；他们共享一个 TLScontact 团队 ID+预约时段。**

应用 ETHOS 原则 #1（"申请就是审计轨迹"）— 跨申请人一致性与每人一致性同等重要。如父亲 France-Visas 写"出行 7/15-22"而母亲写"7/15-23"，那是个标记。

## 何时使用此技能

- 用户从 `/start-here` Q2 范围含多个申请人
- 用户说"我们 N 人家庭"/"团体申请"
- 用户已订个人预约想转为团体
- 用户范围有未成年人（推荐先运行 `/minor-application`，然后此技能）

## 4 个结构性规则

### 规则 1 — 每位申请人一份 France-Visas 申请

即使配偶。即使未成年子女。每人有：
- 自己的 France-Visas 参考号（`FRA-XXXXXXXX-XX`）
- 自己的申请收据 PDF
- 自己的个性化佐证文件清单

为每位申请人单独运行 `/france-visas-form`。

### 规则 2 — 整团一个 TLScontact 团队 ID

每位申请人有了 France-Visas 参考号后，**团队负责人**在 TLS 上创建团队并加入其他人：
- 团队负责人：通常是主要成年人、家庭头或最可能赴约的人
- 用 France-Visas 参考号+出生日期+护照加入每位申请人
- TLS 生成单一团队 ID（`XXXXXXXX`）

团队 ID 是将申请人连接到同一预约时段的纽带。

### 规则 3 — 每团一个预约时段

TLS 在单一时段安排团队预约（30-60 分钟取决于团队大小）。所有申请人一起赴约。**每位申请人必须亲到** — 生物识别+照片是个人的。

### 规则 4 — 跨申请人文件一致性

家庭共享文件（如覆盖 4 人的住宿订单）覆盖所有申请人。每人文件（护照、照片、France-Visas 表）每人独特。

姓名、地址、日期、雇主参考、担保人信息 — 共享时必须跨申请人一致。

## 按申请人分解

| 文件 | 每人？ | 备注 |
|---|---|---|
| 护照（+复印件） | 是 | 各人独特 |
| 照片 | 是 | 各人独特 |
| France-Visas 表 | 是 | 各人独特参考号 |
| 求情信 | 是 | 各人独特；未成年人由父母口吻起草 |
| 银行流水 | 每成年人 | 未成年人通常不需自己的；父母覆盖 |
| 工作信+工资单 | 每工作成年人 | 配偶无工作：跳过或担保人信 |
| 保险证明 | 每申请人（或家庭保单各人列名） | 按人覆盖，非合计 |
| TLS 预约 | 团队（一个时段） | 所有申请人一起赴约 |
| 住宿 | 团队共享 | 家庭一份订单 |
| 行程 | 团队共享 | 出行一份行程 |
| 求情信 | 每人 | 各讲自己的故事 |
| Attestation d'Accueil（如探亲） | 团队共享 | 单份 Attestation 列所有访客 |
| 结婚证/出生证明 | 按需 | 配偶案例+未成年人案例 |
| 担保人信 | 按担保人关系 | 如一位父母担保其他人，一封担保人信列出所有受担保申请人 |

## 流程

1. **识别团队组成** — 成年人？未成年人？担保关系？
   - 未成年人，为每个孩子路由到 `/minor-application`
   - 担保关系（如丈夫担保妻子）路由到 `/sponsored-application`

2. **识别团队负责人** — 将管理 TLS 团队+作为协调联系人赴约的主要成年人。

3. **排序申请：**
   - 所有申请人各自运行 `/france-visas-form` → 每人得参考号
   - 团队负责人运行 `/tlscontact-form` → 创建团队 → 用参考号加入每人
   - 团队预订一个 TLS 时段

4. **跨申请人一致性检查：**
   - 出行日期在所有 France-Visas 表上一致
   - 住宿地址一致
   - 目的一致（或兼容 — 如配偶"探亲"而用户"旅游"如解释则可）
   - 担保人姓名在所有担保申请上一致

5. **文件分配** — 用上方每人表格产出每人清单。

6. **TLS 预约时段策略** — 3+ 人团队，时段稀缺更严重（更少时段能容纳大团队）。如挣扎则路由 `/find-slot`。

## 常见陷阱

| 陷阱 | 为何有害 | 修复 |
|---|---|---|
| 每人订个人 TLS 时段 | 低效+更少时段选项+多个 TLS 服务费成本 | 取消个人，按团队重订 |
| 申请人 France-Visas 表上出行日期跨人不一致 | 跨申请人审计失败 | 各申请人重提一致日期 |
| 未成年人申请未含父母文件 | 申请在领事停滞 | 提交前为每个未成年人运行 `/minor-application` |
| 担保人信仅列部分受担保申请人 | 未担保的需自己资金 | 重发列所有的担保人信或为未担保提供单独资金 |
| 家庭保单未列每人姓名 | 覆盖模糊 | 向保险商请求列名版 |
| 团队负责人无法赴约 | 团队改期 | 选肯定能赴约的负责人 |
| 混合目的（一旅游、一商务） | 领事故事混淆 | 如每求情信解释则可；可辩护 |

## 路由规则

| 情况 | 建议下一步 |
|---|---|
| 团队含未成年人 | 先为每个孩子 `/minor-application` |
| 团队有担保关系 | `/sponsored-application` 处理担保人文件 |
| 团队大小无时段 | `/find-slot` 含紧迫性+Visa Master 扩展 |
| 5+ 团队 | 考虑 2 子团队（一些中心团队上限 4）；与 TLS 确认 |
| 所有参考号收齐准备预约 | 团队负责人 `/tlscontact-form` |
| 跨团队 80%+ 文件齐 | `/audit-application` 跨申请人审计 |

## 维护者注意事项

- "每申请人一份 France-Visas、整团一个 TLS"结构是基础 — 许多用户假设团队共享 France-Visas 参考号。不共享。
- 一些中心团队上限 4（伦敦）或 5（曼彻斯特）。预约时确认；大团队可能需 2 子团队。
- 公司/旅游团（非家庭），团队负责人是有组织权威的人。动态类似家庭负责人逻辑。
- 团队预约费用结构有益：TLS 服务费按人（非按团），所以无节省。节省是时间（一时段 vs N）和便利（一预约 vs N）。
- 团内一人被拒，其他人申请独立继续。被拒人不拖团。
- 签证费按人。6 岁以下儿童免；6-12 半价；12-17 全价。

# /accommodation-verify

## 这个技能做什么

你是 **Schengen-master 文件工程师（住宿专家）**。你核实用户的住宿证据覆盖行程每一晚、列出每位申请人、符合 TLS 预期。你抓住此领域两个最常见的拒签触发：

1. **空缺夜** — 10 夜行程只订了 7 夜
2. **错的证据类型** — 住亲属家时却交了酒店订单（应交 Attestation d'Accueil）

应用 ETHOS 原则 #1（"申请就是审计轨迹"）— 住宿证据必须与 France-Visas 日期+逐日行程精确匹配。

## 何时使用此技能

- 用户已订住宿，想确认够不够
- 用户住亲友家，不确定该提供什么
- 行程混合酒店+AirBnB+住朋友家
- 用户考虑"订完再退"（别 — TLS 可能查）
- 审计前（在 `/audit-application` 之前跑）

## 住宿类型+所需证据

| 类型 | 所需证据 | 常见陷阱 |
|---|---|---|
| **酒店** | 含申请人姓名、日期、地址的订单确认 PDF | 订单网站显示"测试预订"— 需真实确认 |
| **AirBnB / VRBO** | 订单确认+东道地址+预订 ID | 订房平台只显示入住/退房，不显示按夜 — 可打印收据即可 |
| **青旅** | 同酒店 | 一些青旅不签 PDF — 明确索要 |
| **住朋友/亲属家** | 东道的 **Attestation d'Accueil**（不是酒店订单） | 最易漏的要求；办需 2-4 周 |
| **自有房产** | 房产所有权证明（房契、近期写有申请人名字的水电费） | 罕见但接受 |
| **邮轮/中转** | 邮轮行程+船舱安排 | 适用时下船日住宿也要 |
| **混合（酒店+住宿）** | 每晚单独算 | 空缺夜是杀手 |

## 核实清单

每份住宿：

1. **姓名匹配** — 订单列了你的申请人吗？如两位旅客中只有一位被列，另一位需加入（致电酒店）或自行预订。
2. **日期覆盖** — 订单覆盖所声称的夜数吗？查入住+退房。
3. **地址** — 完整街道地址可见？（France-Visas 地址字段需要。）
4. **退订政策** — 可退到哪天？为求情信记录。
5. **确认号** — 可见？（一些 TLS 中心要求核实。）
6. **货币** — 欧元或英镑均可；其他不常见货币可能需注解。

住宿家庭：

1. **已办 Attestation d'Accueil** — 东道在其 Mairie 签的 Attestation，不是私人信
2. **Attestation 匹配日期** — 覆盖每个住宿夜
3. **Attestation 上的东道地址** — 必须与申请人住宿地一致
4. **原件或公证副本** — TLS 偏好原件
5. **准备时间** — Attestation 需 2-4 周；如行程 < 4 周则标出

## 流程

1. 问用户行程每段：哪里、几晚、什么类型
2. 收集每段证据（或描述）
3. 对每份住宿跑核实清单
4. 建按夜覆盖表
5. 标出空缺+错类型+姓名不符
6. 输出推荐修正

## 路由规则

| 情况 | 建议下一步 |
|---|---|
| 所有夜覆盖、所有姓名匹配 | `/audit-application` |
| 需 Attestation | `/sponsored-application`（东道文件）+`/timeline-planner`（准备时间影响） |
| 空缺夜 | 填空缺；如预算受限，降级城市/酒店而非省略夜数 |
| 共享订单缺姓名 | 联系东道/酒店添加 或 缺失夜数单独订 |
| 用户考虑"批后退订"方案 | 标为风险；TLS 核实订单；订单+赴约之间取消会被标记 |

## 常见陷阱

| 陷阱 | 为何有害 | 修复 |
|---|---|---|
| 只交入住/退房日期而无按夜覆盖 | 看上去可疑 | 打印含所有夜数项目的完整订单 |
| 酒店订单在一城但行程列另一城 | 内部不一致 | 住宿与行程逐城匹配 |
| AirBnB 东道不开收据 | 一些东道是新手 | 用 AirBnB 官方预订收据页 |
| 用"待确认"占位订单 | 拒签触发 | 申请前确认订单 |
| 住亲属家却交酒店订单 | 即使更便宜，也是错误证据类型 | 住东道家时 Attestation 必备 |
| 晚归航班忘最后一晚住宿 | 空缺夜=拒签 | 如次日返家，最后一晚仍是晚 |

## 维护者注意事项

- Attestation d'Accueil 是文件工程师最常见的意外 — 如用户提到住任何认识的人家，`/start-here` 早点标出。
- AirBnB Plus / Luxe 订单比无评价的廉价房间可信度更高；如申请人财务紧，优先选好评东道。
- Booking.com 的"Genius"等级显示申请人忠诚度 — 对回头客是小小正信号。
- 长住（如 21 天），住宿成本累计；如住宿成本 > 申报预算 50%，标出。
- 对有可退订单的用户 — 签证批准前保留。一些申请人被拒，不可退订单上亏钱。

# /track-application

## 这个技能做什么

你是 **Schengen-master 补救顾问（追踪专家）**。用户在 TLS 赴约后提交了，现在在等。你的工作：

1. 告诉他们在哪追踪（TLS 追踪器 URL+登录）
2. 解释每个状态含义（翻译"Documents in transit"→"这是正常的，仅在转运中"）
3. 设现实时间线（法国通常 7-15 个工作日）
4. 标记何时担心（何时耐心）
5. 为两种结果（批准+拒签）做准备

应用 ETHOS 原则 #11（"偏向行动"）— 状态模糊时给清晰解释，不要"可能任何"。

## 何时使用此技能

- 用户在 TLS 提交后问"什么时候能听到回音"
- 用户查 TLS 追踪器问"这状态什么意思"
- 用户等得比预期长焦虑
- 用户收到状态变更通知想了解上下文
- 用户想根据决定时间规划出行

## 在哪追踪

| 来源 | URL | 显示什么 |
|---|---|---|
| **TLScontact 追踪器** | https://visas-fr.tlscontact.com/en-us — 登录 | 实物申请包的实时状态（转运+在领事+决定返回） |
| **France-Visas 门户** | https://france-visas.gouv.fr/en/web/france-visas — 登录 | 申请元数据；不如 TLS 追踪器详细 |
| **邮件** | （France-Visas+TLS 用的邮箱） | 状态变更通知 |

建议用户在等待期间**每天查一次** TLS 追踪器。更频繁=焦虑+无新信息；更少=错过通知。

## 典型时间线

法国从英国 TLS 中心（2026-05-24 已核实）：

| 天 | 状态 | 发生什么 |
|---|---|---|
| T-0（赴约日） | 文件在 TLS 收到 | 实物包收集；生物识别采集；费用付清 |
| T+1 至 T+2 | 文件转运至领事 | TLS 快递递送至法国领事（伦敦） |
| T+3 至 T+10 | 申请在领事审查 | 领事官员评估 |
| T+7 至 T+15 | 决定做出；护照返回 TLS | 决定传达；包返回 |
| T+1 至 T+3（返回后） | 用户领取或快递送达 | 最后一步 |

**典型总计：从赴约到护照在手 7-15 个工作日**。一些申请 4-5 天返回；一些 20+ 天（始终工作日，非自然日）。

**不必担心，除非：**
- 已过 15 个工作日且无状态更新
- 状态"审查中"超过 10 个工作日
- 赴约后 48+ 小时 TLS 追踪器仍无任何状态

## TLS 追踪器状态解码

追踪器用神秘状态标签。每个通常含义：

| 状态（TLS UI） | 含义 | 担忧级别 |
|---|---|---|
| "Documents received at TLScontact" | 赴约后初始状态 | 无 — 预期 |
| "Documents in transit to Consulate" | 快递在送包 | 无 |
| "Documents received at Consulate" | 在法国领事；审查开始 | 无 |
| "Application under review" | 领事官员评估 | 前 10 个工作日无 |
| "Documents in transit from Consulate" | 决定做出；包在返回 | 无 — 快完了 |
| "Decision made — passport at TLScontact" | 准备领取或快递发出 | 行动：领取/等快递 |
| "Documents ready for collection" | 同上；就在中心 | 行动：领取 |
| "Sent by courier" | 如用户付了快递 | 行动：通过快递服务追踪 |
| "Request for additional information" | 领事要更多文件 | 行动：立即回应 |
| "Application refused" | 包内有拒签信 | 行动：领取；运行 `/refusal-appeal` |
| "Application approved" | 包内有签证贴纸 | 行动：领取；运行 `/first-trip`（v0.3） |

## 何时担心

| 症状 | 担忧级别 | 行动 |
|---|---|---|
| 赴约后 48h 无状态更新 | 中 — TLS 可能尚未更新追踪器 | 再等 24 小时；仍无则联系 TLS |
| "审查中" 超过 10 个工作日 | 低 | 正常上限；等到第 15 天再联系 |
| "审查中" 超过 15 个工作日 | 中 | 邮件 TLS 询问；一些领事发延期通知 |
| "审查中" 超过 20 个工作日 | 高 | 联系 TLS+法国领事直接；可能在额外审查 |
| 收到"Request for additional information" | 高 — 时限敏感 | 仔细读请求；在所述截止内回应（通常 7-14 天）；如错过申请可能自动拒绝 |
| 状态倒退（如从"审查中"回到"在转运") | 低 — 通常追踪器故障 | 等 24 小时；如持续则联系 TLS |
| 关于"premium service"或"expedited fee"的邮件 | 可疑 | 可能钓鱼 — TLS 赴约后不会发邮件推销 |

## 每阶段做什么

### 阶段 1 — 赴约后前 48 小时

- 状态：" Documents received at TLScontact" → "Documents in transit"
- **行动：无。** 如无邮件不要恐慌；追踪器更新不总是即时。

### 阶段 2 — 第 3-10 天（典型审查窗口）

- 状态："Application under review at Consulate"
- **行动：无。** 抵制每天多次查 TLS 的冲动。
- 利用此时间：收集签证领取所需地址；规划旅行保险开始日期（常与签证开始同步）。

### 阶段 3 — 第 7-15 天（可能决定）

- 状态变为"Decision made — passport at TLScontact"
- **行动：及时领取。** TLS 中心有领取窗口（通常周一至周五 14:00-16:00）。

### 阶段 4 — 领取日

- 带：原始护照收据+身份证件
- 不要自己打开密封信封 — 领事可能要密封完整用于入境核实。
- 回家后小心打开。内有：
  - **批准：** 护照上的签证贴纸。核实日期+次数。
  - **拒签：** 正式拒签信。运行 `/refusal-appeal`。

### 阶段 5 — 决定后（如批准）

- 核实签证贴纸有：
  - 正确全名（与护照一致）
  - 正确护照号
  - 正确入境/离境日期（覆盖你的出行）
  - 正确入境次数（单次/多次）
  - "Schengen states"或"Type C"标示

- 如有错误：立即联系 TLS 在出行前更正。

## 路由规则

| 状态 | 建议下一步 |
|---|---|
| "审查中" + <10 个工作日 | 等；每天查 |
| "审查中" + >15 个工作日 | 通过支持线联系 TLS |
| "决定做出 — 在 TLScontact" | 领取（亲自或按预约选择的快递） |
| "申请批准" | `/first-trip`（v0.3）— 入境指引 |
| "申请拒签" | 立即运行 `/refusal-appeal` |
| "Request for additional information" | 仔细读请求；在截止内回应；如需要路由到具体技能（如保险请求 `/insurance-check`） |
| 赴约后 48h 状态未更新 | 再等 24 小时，然后联系 TLS |
| 用户想边等边规划出行 | 保险开始日期检查；航班出票考虑；住宿锁定 |

## 常见陷阱

| 陷阱 | 为何有害 | 修复 |
|---|---|---|
| 每小时查追踪器 | 焦虑+无新信息 | 每天查一次足够 |
| 批准前订不可退航班 | 拒签风险损失 | 等批准；或订可退 |
| 错过"Request for additional information"截止 | 自动拒签 | 等待期间每天查邮件 |
| 打开密封信封核实签证 | 可能无效入境核实 | 不要打开；让边检看密封 |
| 在签证开始日期当天精确出行 | 边检可能质疑 | 开始日期后一天出行作缓冲 |
| 签证批准但出行日期已过 | 签证是过去日期；不能用 | 如出行推迟，可能需新申请 |

## 维护者注意事项

- 7-15 个工作日时间线对法国-英国是典型；可更快（低季 3-5 天）或更慢（夏季高峰 20+）。
- 一些申请人审查期间会收到领事电话 — 这是正常额外核实，非拒签信号。
- 如用户外出而签证在缺席期间批准，TLS 持护照最多 30 天；更长=额外费用。
- 决定延迟的未成年人申请：常因额外未成年人特定检查；不要惊慌。
- 团体申请，如以团体预约则所有人状态一同更新。如一人"审查中"而其他"完成"，那不寻常 — 标记给 TLS。
- "Request for additional information"截止至关重要。错过可使申请无效。即使所述截止较长，默认 48 小时内回应请求。

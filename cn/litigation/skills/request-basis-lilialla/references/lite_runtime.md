# Lite Runtime

Use this reference for ordinary student, litigation, arbitration, and research tasks. It keeps runtime small.

## Runtime Core

Only keep these visible during legal analysis:

1. Scenario: study, litigation, arbitration, research, or catalog/build.
2. Claim goal: who demands what from whom.
3. Fact discipline: separate assertion, evidence content, fact to prove, disputed fact, legal evaluation, and model inference.
4. Request lifecycle: right arises, not extinguished, exercisable, defenses/counter-defenses.
5. Concept control: use concept cards for material professional terms; otherwise make temporary cards.
6. Rule-obligation support: use a matching group if helpful; otherwise create a temporary group and mark it `model_inference/unverified`.
7. Norm decomposition: when academic precision is needed, expand only the selected request basis into main norm, auxiliary norms, defenses, counter-defenses, extinguishment, and exercisability.
8. Source and verification labels: do not state current law or court practice as verified without authority research.

## Hidden Maintenance Layer

Do not expose these to ordinary users unless the task is maintenance:

- schema details;
- resource manifest mechanics;
- generated indexes;
- concept candidate batches;
- catalog review batches;
- validation internals.
- full norm-decomposition seed data.

## Output Rule

Prefer the smallest output that still shows:

- claim goals;
- candidate request bases;
- lifecycle gates for detailed bases;
- norm tree nodes when the user asks for precision;
- material concepts;
- evidence gaps if practical;
- verification tasks.

Do not expand every template section when the task is simple.

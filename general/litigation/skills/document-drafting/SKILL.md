# Skill：法律文书与沟通文本起草

## 事项记忆要求

- 本技能是分析镜头。默认把结果写入会话回复、`matter.md` 或目标交付文件。
- 只有长期协作、审计追踪或用户明确要求时，才更新 `skill_outputs.md`。
- 如果本技能没有实际执行，不能在报告中暗示已完成；如果信息不足，输出缺口、影响和下一步。


## 适用场景

用户需要起草或优化：

- 事实确认消息。
- 协商函。
- 催告函。
- 投诉材料。
- 调解申请。
- 起诉状框架。
- 答辩状框架。
- 证据目录。
- 庭审陈述提纲。
- 总结报告。
- 合同审查总结。
- 合同或补充协议草案。

## 目标

1. 将事实、证据、请求转化为清晰文本。
2. 降低情绪化和法律结论过度的问题。
3. 保留必要的法律立场和证据指向。
4. 避免不当承认、威胁、诽谤或泄露隐私。
5. 对案件工作台事项，先形成 `pleading_framework.md`，再决定是否继续起草正式文书。
6. 将工作底稿转化为面向用户或外部对象的清晰交付文件。

## 输入

- 文书用途。
- 接收对象。
- 用户身份。
- 事实摘要。
- 证据清单。
- 诉求。
- 希望语气。
- 是否用于正式程序。
- 输出语言。
- 是否为报告的一部分。

## 工作流

### 1. 明确文书功能

不同文书有不同目标：

| 文书 | 目标 |
|---|---|
| 事实确认消息 | 锁定对方陈述和关键事实 |
| 协商函 | 推动解决，保留证据 |
| 催告函 | 明确期限和后果 |
| 投诉材料 | 向平台/行政机关说明事实和请求 |
| 起诉状 | 明确当事人、请求、事实理由、证据 |
| 答辩状 | 反驳请求、事实和法律依据 |
| 证据目录 | 说明证据名称、来源、证明对象 |
| 文书框架 | 在正式起草前固定请求、事实叙事、法律依据、证据附件和表达风险 |
| 报告 | 综合事实、证据、来源、分析和建议，给用户一份可读、可执行、可保存的结论文件 |
| 合同审查总结 | 摘要条款风险、修改建议和签署前清单 |
| 合同草案 | 固化交易结构、权利义务、风险分配和违约责任 |

### 2. 文书结构

通用结构：

```text
标题
收件对象
身份与关系
事实时间线
证据对应
请求事项
期限或下一步
保留权利
落款
```

案件工作台的 `pleading_framework.md` 结构：

```text
文书类型和目标读者
请求或抗辩目标
事实叙事框架
法律依据和法律规则适用边界
证据附件地图
备选请求或兜底主张
提交前必须核验的事实
表达风险和不宜写入内容
```

报告文书结构：

```text
标题
目录
目的与范围
核心结论摘要
分析范围与可靠性说明
关键事实/合同背景
主要法律问题/条款风险
分析与理由
行动清单/签署建议
来源与引用风险
待补充信息
重要提示
```

### 3. 降噪处理

将以下表达改写：

- 情绪攻击 → 事实描述。
- 道德评价 → 证据支持的行为描述。
- 绝对结论 → 保留性法律表述。
- 威胁语气 → 合法权利保留。

### 4. 风险审查

审查是否存在：

- 自认不利事实。
- 超出证据的指控。
- 泄露隐私。
- 威胁、胁迫或诽谤。
- 错误法律路径。
- 金额计算不清。

## 输出格式

```markdown
## 文书用途与风险提示

## 草稿

[正文]

## 逐项说明
| 段落 | 目的 | 证据依据 | 风险 |
|---|---|---|---|

## 可替代表达
| 强硬版 | 中性版 | 温和版 |
|---|---|---|

## 使用前核验清单
1. 当事人信息是否准确但不过度暴露隐私。
2. 日期、金额、证据编号是否准确。
3. 是否保留原始证据。
4. 是否需要律师审阅。
```

## 质量检查

- 文书请求清楚。
- 事实与证据对应。
- 避免违法威胁和诽谤。
- 不编造法条和案例。
- 报告必须综合 `matter.md`、`sources.md` 和已存在的相关工作文件，不得只复制底稿。
- 文件名和正文语言默认跟随用户输入语言。
- 复杂事项报告应交给 `skills/17_final_synthesis/` 执行；用户要求报告文件时输出 Markdown 报告，用户明确要求 PDF 时再输出 PDF 报告。
- 进入程序或准备提交材料时，先更新 `pleading_framework.md`；材料不足时不得输出看似可直接提交的正式文书。

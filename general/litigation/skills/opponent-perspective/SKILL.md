# Skill：对方视角与抗辩模拟

## 事项记忆要求

- 本技能是分析镜头。默认把结果写入会话回复、`matter.md` 或目标交付文件。
- 只有长期协作、审计追踪或用户明确要求时，才更新 `skill_outputs.md`。
- 如果本技能没有实际执行，不能在报告中暗示已完成；如果信息不足，输出缺口、影响和下一步。


## 适用场景

用户需要预判对方怎么反驳、怎么解释矛盾、怎么攻击证据、怎么降低责任或谈判压价时使用。

## 目标

1. 模拟对方最可能的事实版本。
2. 识别对方会承认、否认、转移、淡化的点。
3. 预测证据攻击路线。
4. 将对方说法转化为反制命题，嵌入争议焦点关系图。
5. 设计己方反制和补证计划。

## 输入

- 用户主张。
- 对方已有表态。
- 证据台账。
- 矛盾矩阵。
- 法律要件矩阵。

## 工作流

### 1. 对方利益定位

判断对方最想达成什么：

- 完全免责。
- 降低金额。
- 拖延时间。
- 避免公开或处罚。
- 保持合作关系。
- 转移责任给第三人。
- 迫使用户放弃部分请求。

### 2. 对方抗辩分类

| 抗辩类型 | 典型说法 | 反制方向 |
|---|---|---|
| 否认事实 | 没有发生、没有承诺、没有收到 | 客观证据、时间线、第三方记录 |
| 重新解释 | 发生了但含义不同 | 上下文、后续履行、常理 |
| 履行抗辩 | 已经履行或用户未配合 | 履行证据、催告记录、缺陷记录 |
| 因果抗辩 | 损失不是我造成 | 因果链、替代原因排除 |
| 金额抗辩 | 金额过高、无依据 | 票据、合同、市场价格、计算表 |
| 过错抗辩 | 用户也有错 | 减损证据、沟通记录 |
| 程序抗辩 | 管辖、时效、主体不适格 | 程序核验、主体证据 |

### 3. 对方证据攻击

模拟对方会质疑：

- 证据是否完整。
- 截图是否断章取义。
- 录音取得是否合法。
- 合同是否有效。
- 签名/盖章/授权是否真实。
- 转账是否对应本案。
- 证人是否有利害关系。

### 4. 反制设计

对每条抗辩设计：

```text
对方说法 → 对方依据 → 己方反证 → 补强动作 → 提问锁定
```

反制必须回到 `docs/LEGAL_REASONING.md` 的争议焦点层级：该抗辩是在攻击母命题、条件命题、金额命题、程序命题还是证据命题。

## 输出格式

```markdown
## 对方总体策略预测

## 对方抗辩地图
| 编号 | 对方可能说法 | 攻击的争议焦点层级 | 目的 | 依据 | 己方反制 | 补证动作 | 风险 |
|---|---|---|---|---|---|---|---|

## 对方证据攻击预测
| 被攻击证据 | 对方可能质疑 | 影响 | 补强方式 |
|---|---|---|---|

## 己方漏洞
| 漏洞 | 对方利用方式 | 修复方式 |
|---|---|---|

## 可用于反制的提问
```

## 质量检查

- 对方视角要真实，不要把对方写成明显愚蠢。
- 必须包含对己方不利点。
- 每条反制都要有证据或补证动作。
- 每条主要抗辩都要说明其攻击的争议焦点层级和对全案的影响。
- 不建议通过违法或不当方式压迫对方。

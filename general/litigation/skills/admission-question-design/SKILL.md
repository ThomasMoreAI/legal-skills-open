# Skill：合法自证与承认事实提问设计

## 事项记忆要求

- 本技能是分析镜头。默认把结果写入会话回复、`matter.md` 或目标交付文件。
- 只有长期协作、审计追踪或用户明确要求时，才更新 `skill_outputs.md`。
- 如果本技能没有实际执行，不能在报告中暗示已完成；如果信息不足，输出缺口、影响和下一步。


## 适用场景

用户希望通过聊天、电话、邮件、调解、庭审或质证，让对方对关键事实作出明确回应，或暴露其说法矛盾时使用。

## 重要边界

本技能中的“自证”不是欺骗、胁迫、威胁或诱导虚假陈述。它只指：通过合法、克制、清楚、可记录的问题，让对方对真实事实、既有行为、既有文件或争议焦点作出明确表态。

禁止：

- 诱导对方说假话。
- 冒充身份。
- 非法录音、偷拍、盗取聊天记录或账户信息。
- 威胁公开隐私、骚扰亲友、恶意举报。
- 断章取义剪辑对方回复。

## 目标

1. 锁定基础事实。
2. 缩小争议范围。
3. 促成对方承认关键事实。
4. 在对方否认时形成矛盾记录。
5. 为证据补强、调解、庭审发问提供素材。

## 提问原则

### 1. 单事实原则

每个问题只问一个事实。

错误：

```text
你是不是承认你当时答应了、后来又反悔、还造成了我的损失？
```

较好：

```text
某日你是否收到过这份文件？
```

### 2. 先基础后关键

顺序：

```text
身份/关系 → 文件/时间 → 行为 → 承诺/通知 → 后果 → 责任争议焦点
```

### 3. 先开放后封闭

先让对方解释，再用封闭问题确认：

```text
你当时理解这句话是什么意思？
所以你的意思是，你确认曾收到该通知，对吗？
```

### 4. 避免结论性词汇

少用“欺诈、恶意、违法、违约”等结论性词，先问事实。

### 5. 记录完整语境

保留完整对话，不只保存有利片段。

## 提问路径

### A. 确认关系

- “我们之间是否存在某项合同/交易/劳动/租赁/服务关系？”
- “该关系开始于何时？”
- “当时由谁负责沟通？”

### B. 确认文件

- “你是否收到过这份文件？”
- “收到时间大约是什么时候？”
- “你当时是否提出过异议？”

### C. 确认行为

- “某日是否发生过该事项？”
- “当时是谁作出的决定/通知/承诺？”
- “你是否采取过某项后续措施？”

### D. 确认金额或损失

- “该笔款项是否由你方收取？”
- “你方是否知道该支出的用途？”
- “你方是否曾对金额提出异议？”

### E. 锁定矛盾

- “你刚才说没有收到，但某日回复中提到‘已看’，这两点如何解释？”
- “如果你方认为未约定该事项，为什么之后又按该事项执行了一段时间？”

```markdown
## 提问顺序

|---|---|---|---|---|---|---|

## 不建议问法
| 问法 | 问题 | 替代表达 |
|---|---|---|

```

## 质量检查

- 问题不诱导虚假陈述。
- 问题不使用威胁或侮辱。
- 每个问题都有证明目标。
- 预设了对方承认和否认两种结果的价值。

# Skill：案例参考与规则学习

## 事项记忆要求

- 本技能是分析镜头。默认把结果写入会话回复、`matter.md` 或目标交付文件。
- 只有长期协作、审计追踪或用户明确要求时，才更新 `skill_outputs.md`。
- 如果本技能没有实际执行，不能在报告中暗示已完成；如果信息不足，输出缺口、影响和下一步。


## 适用场景

用户希望查找类似案例、学习裁判思路、比较结果影响因素、提取可用于文书或谈判的规则时使用。

## 目标

1. 设计可执行的检索关键词。
2. 区分法规、指导案例、类案、裁判观点和文章评论。
3. 提炼案例中的事实相似点、差异点和裁判理由。
4. 优先检索所属国家/管辖权的官方法律条文、案例和判决文件。
5. 将可引用来源写入事项文件夹中的 `sources.md`。
6. 对每条规则提炼适用边界、例外限制和引用风险。
7. 防止误用案例或编造引用。

## 输入

- 法域。
- 案件类型。
- 核心事实。
- 争议焦点。
- 用户请求。
- 对方抗辩。
- 事项文件夹路径。

## 工作流

### 1. 提取检索要素

从案件中抽取：

- 法律关系关键词。
- 行为关键词。
- 损害关键词。
- 抗辩关键词。
- 证据关键词。
- 程序关键词。

示例结构：

```text
法律关系 + 行为 + 损害 + 抗辩 + 证据
```

### 2. 检索优先级

优先级建议：

1. 现行法律法规、司法解释、官方规则。
2. 最高级别或本法域高权威裁判规则。
3. 同地区、同案由、同争议焦点、近年案例。
4. 专业文章和评论，作为辅助理解，不作为直接依据。

### 3. 联网执行层

如果用户需要实际检索，而不是只要关键词设计，应使用浏览器、官方网页、权威法律数据库、搜索引擎或宿主环境提供的外部工具。

执行规则：

- 先确认法域，再选择对应官方来源，例如全国人大法律法规库、最高人民法院官网、裁判文书平台、政府部门官网、地方法院或行政机关官网。
- 优先使用官方域名限定查询，例如 `site:flk.npc.gov.cn 合同 迟延履行`。
- 搜索结果必须核验来源、发布日期、效力状态、适用地域和是否仍然有效。
- 找不到官方来源时，可以使用权威数据库、法院发布、政府转载或专业资料作为线索，但必须标记“待核验”。
- 将检索结论写入事项文件夹的 `sources.md`，不要只留在聊天记录中。
- 对访问失败、无结果、非官方来源、旧法或不可直接类比的结果必须显式标记。

### 4. 案例相似性评分

| 维度 | 问题 |
|---|---|
| 法律关系 | 是否同类关系 |
| 核心行为 | 对方行为是否相似 |
| 损害类型 | 损害是否相似 |
| 证据结构 | 证据是否相似 |
| 抗辩类型 | 对方抗辩是否相似 |
| 程序阶段 | 一审、二审、再审、仲裁等是否可比 |
| 地区和时间 | 是否同法域、近年、规则未变 |

### 5. 提炼裁判规则

对每个案例提炼：

```text
案件事实 → 争议焦点 → 法院认定 → 关键证据 → 裁判理由 → 可借鉴点 → 不可类比点
```

同时按 `docs/LEGAL_REASONING.md` 输出规则边界：法域、时间、主体、行为、要件、例外、证明责任、法律后果和类推风险。

### 6. 引用规范

引用前必须核验：

- 来源 URL。
- 访问日期。
- 案号。
- 法院或发布机构。
- 发布/裁判日期。
- 是否生效。
- 是否被改判、撤销或规则过时。
- 是否只是个案事实判断。

## 质量检查

- 不编造案例或案号。
- 不把单个案例机械套用为必然结果。
- 明确相似点和差异点。
- 每条可迁移规则都必须有适用边界，不能只摘结论。
- 涉及最新法规或案例时必须核验。
- 未检索到官方来源时，不得伪造补齐；应说明检索失败、来源不可访问或需要继续核验。
